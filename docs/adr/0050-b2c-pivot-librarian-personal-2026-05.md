# ADR 0050 — 사서 B2C "몰래 쓰기" 방향 전환 (Cycle 68)

- 상태: Accepted (2026-05-06·PO 명시 결정)
- 일자: 2026-05-06
- 트리거: PO "결제권자 = 결제자 일치 = 수익 가능"·"사서 B2C 몰래 쓰기"·"Supabase OK"

## Context

PO 정직 통찰 (Cycle 67~68 누적):
1. "사용 ≠ 매출" = 사서 사용 OK·결제 X
2. 8 페르소나 분석 = 7/8 = **결제 권한 X** (P8 도서관장만 가능)
3. B2B (학교·자치구·공공) = 결재선 = 보수·시간 ↑
4. **B2C·"몰래 쓰기"** = 결제권자 = 결제자 = 수익 직진

→ **방향 전환 필수**·B2B 영업 채널 = 부분 정지·B2C = 1순위.

## Decision

### A. 사서 B2C "몰래 쓰기" 모델

#### 핵심 가설
- 사서 = "직장 운영위 결재 = 부담·정치"
- "몰래·혼자·시간 절감" = 매력적
- ₩9,900~₩30K/월 = 사서 본인 시급 환산 = 충분 결제

#### 차별화
- **결재선 X** = 즉시 결제 (체크카드·자동)
- **세금계산서 X** = B2C·간편결제
- **도서관 IT 부서 무관** = .exe 사서 컴퓨터 또는 URL
- **시간 절감 = 사서 본인** = 퇴근 시간 ↑·NPS ↑·승진 ↑
- **"몰래" 메시지** = 사서 자유 = 결제 의지 ↑

#### 시장
- 한국 사서 약 100,000명 (도서관·학교·자관·전문 도서관 등)
- ₩9,900/월 × 5,000명 = **₩49.5M/월 = 캐시카우 가능**
- ₩30,000/월 × 1,000명 = **₩30M/월**

### B. Supabase 부활 (B2C 한정)

ADR 0047 "Supabase 미도입" → **부분 supersede**:

| 영역 | 도입 |
|---|---|
| **B2C (사서 개인)** | ✅ Supabase Auth (50K MAU 무료·Cycle 11+ 활성) |
| B2B (학교·자치구·공공) | ❌ AWS Cognito Seoul (Phase 3) |

#### 이유
- **자관 데이터 = 사서 컴퓨터** (헌법 §14·invariant 12 유지)
- 사서 PII만 = 이메일·해시 PW·결제 history
- PIPA §28의8 = 6수신자 (Anthropic·AWS·PortOne·Google·Cloudflare → +Supabase)
- privacy-policy v2 발행 의무 (간단·운영위 결재 X·B2C)
- 도서관 RFP·CSAP 부담 X (B2B X = RFP X)
- Supabase 무료 50K MAU = 사서 5만명 가능

### C. 영업 메시지 전환

#### 기존 B2B (5 페르소나)
- "자료구입비 3% 효율" (학교운영위)
- "자치구 단관 수의계약" (자치구)
- "도서관장 KPI" (P8)

#### 신규 B2C "몰래 쓰기"
- **"퇴근 시간 = 본인 것"**
- **"결재 X = 본인 결제 = 즉시"**
- **"운영위 모름·혼자 사용·시간 절감"**
- **"사서 시급 ₩20K × 6분/권 × 100권/월 = ₩200K 절감 = ₩9,900/월 = 20:1 ROI"**

### D. 가격 전환

기존 4 플랜 (Cycle 11) = B2B 유지 + B2C 신규:

| 플랜 | 영역 | 가격 |
|---|---|---|
| **B2C 사서 개인** (신규·1순위) | "몰래 쓰기"·체크카드 | **₩9,900/월** |
| **B2C 사서 Pro** (신규) | + AI 분류·표지 OCR | **₩19,900/월** |
| 작은도서관 (B2B·기존) | 자치구 결재 | ₩30K/월 |
| 학교 (B2B) | 운영위 결재 | ₩50K/월 |
| 공공 (B2B) | 시청 결재 | ₩150K/월 |
| 기관 (B2B) | 분관 일괄 | ₩300K~/월 |

→ **B2C ₩9,900 = 사서 본인 = 결제권자 = 결제자**.

## Alternatives

1. **B2B 유지·B2C 미진입** = 거부 (PO "수익 = 1순위" 정합·결제 권한 차단)
2. **B2C만·B2B 폐기** = 거부 (P8 도서관장 = 가능·미래 옵션)
3. **B2C + 다른 SaaS 병행** (자동 클리커) = 1인 SaaS 한계·하지만 후보 박제 OK

## Consequences

### Positive
- ✅ 결제 권한 = 결제자·수익 직진 가능
- ✅ Supabase Auth 활성·통합 결제 (PortOne v2)
- ✅ 영업 채널 = 사서 카페·LinkedIn·콜드 메일 (학교운영위 X)
- ✅ 도서관 RFP·CSAP·세금계산서 부담 X (B2C)
- ✅ Cycle 60+ 사서 친화 UI·페르소나 = 100% 재사용
- ✅ "몰래 쓰기" = 신규 차별화 메시지

### Negative
- ⚠ B2C ₩9,900 = 단가 ↓·but 시장 대량 (5,000명 = ₩49.5M/월)
- ⚠ Supabase = privacy v2 발행 의무 (6수신자)
- ⚠ 사서 본인 결제 = top 5%만 가능 (95% = 자가 사용 또는 직장 결제 의존)
- ⚠ 인터뷰 0건·가설·PMF 결정 = SALES-1 후

### Neutral
- ADRs: 0049 → **0050**
- ADR 0047 (Supabase) 부분 supersede·B2C 활성
- Cycle: 67 → 68
- 영구 invariant 12 유지 (자관 데이터 = 사서 컴퓨터)
