`$ARGUMENTS` 코드를 설명하세요.

## 5층 설명 구조

### 1층: 한 줄 요약
이 코드가 무엇을 하는지 한 문장.

### 2층: 책임 (Responsibility)
- 이 코드의 입력은 무엇이고 출력은 무엇인가
- 이 코드가 책임지지 **않는** 것은 무엇인가
- 호출되는 위치 (grep으로 찾아서)

### 3층: 흐름 (Flow)
순서대로:
1. ...
2. ...
3. ...
주요 분기·예외 처리 포인트 표시.

### 4층: 설계 결정 (Why)
**가장 중요한 부분**. 추측 금지.
- `git log -p <file>`로 도입 시 PR/커밋 메시지 확인
- `git blame`으로 어느 라인이 언제·왜 변경됐는지
- decisions.md에 관련 결정 있는지
- 주석에서 단서 찾기

각 비자명한 결정에 대해:
- 무엇이 대안이었는가
- 왜 이걸 선택했는가
- 어떤 트레이드오프가 있는가

설계 의도가 추적 안 되면 솔직히 "추적 불가"라고 표시.

### 5층: 위험 신호 (Smells)
- 100줄 넘는 함수
- 깊은 중첩 (4단계 이상)
- 매직 넘버
- 같은 패턴이 여러 곳에 복사
- "TODO", "FIXME", "HACK" 주석
- 테스트 누락 (테스트 파일 grep)

각 신호에 대해 "왜 위험한지" + "고치면 무엇이 깨질 수 있는지" 명시.

## 출력 톤
- 솔직하게. "잘 짜여있다"고 거짓말 금지.
- 모르는 것은 "모름" 또는 "추적 불가"로.
- 추측은 "(추측)" 접두.
- 이 코드의 다음 작업자(=미래의 자신)에게 도움 되는 것이 목표.
