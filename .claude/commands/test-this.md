`$ARGUMENTS`에 대한 테스트를 작성하세요.

## 절차

1. **현재 테스트 컨벤션 파악**:
   - 프로젝트에서 기존 테스트 1-2개 찾아 읽기 (vitest? pytest? jest?)
   - `package.json` / `pyproject.toml`에서 테스트 명령 확인
   - 동일한 스타일·구조 따라가기

2. **대상 파일 분석**:
   - 공개 함수 목록
   - 입력·출력 시그니처
   - 에러 분기

3. **테스트 케이스 설계** (각 함수당):
   - **Happy path**: 일반적 입력 → 기대 출력
   - **Edge case**: 빈 입력, null, 0, 음수, 매우 큰 값
   - **Error case**: 잘못된 입력 → 적절한 에러
   - **Boundary**: 경계값 (off-by-one)

4. **모킹 결정**:
   - DB·외부 API·파일 시스템 호출은 모킹
   - 시간(`Date.now()`)도 모킹 (재현성)
   - 모킹은 테스트 가독성을 해치지 않는 선에서

5. **테스트 작성·실행**:
   - 1개씩 빨간색 → 통과 → 다음
   - 전체 통과 후 커버리지 확인 (`npm run test:coverage` 등)
   - 커버되지 않은 분기에 테스트 추가

6. **검증**:
   - 의도적으로 코드 한 줄 깨뜨려서 테스트가 잡는지 확인 (mutation test 미니버전)
   - 잡지 못하면 그 테스트는 실효성 없음 → 다시 작성

## 출력
- 테스트 파일 경로
- 추가된 테스트 케이스 목록
- 커버리지 변화 (가능 시)
- 잡지 못한 분기가 있으면 명시

규칙:
- "이 코드가 동작한다"가 아니라 "이 동작이 명세대로다"를 검증.
- 구현 디테일이 아닌 행동(behavior) 테스트.
- 테스트 자체가 깨질 때 무엇이 잘못됐는지 메시지로 알 수 있게.
